# First approved website action on Linux

The first live action may fill one empty, unsaved textbox with the public value `WEIR-CANARY`. Matt selected the inventoried `lugos-host` Linux deployment on November 22. The original policy specifies the owner, passkey decisions, enrollment digest, one-use budget, receipt and quarantine rules. All of those rules apply on Linux. Windows compatibility is tracked independently. [Production effect policy](production-effect-policy.md)

## Host and browser

The trusted host owns enrollment, TLS verification, captures, Fade credentials, decision verification and the durable grant. Only a separate host reader may fetch the enrolled HTTPS document. It must validate the exact bytes, headers and origin, close the upstream connection, then supply those bytes through a single-use document route. The browser has no network access at any point. It cannot pass a URL to that reader. Use a new anonymous Chromium context, enable its native sandbox, disable page JavaScript and service workers, and admit exactly one top-level navigation. Refuse extra requests, frames, forms, page replacement and persistent storage.

Run the driver and the entire browser tree under a dedicated, unprivileged systemd service. Give the browser a private network, PID, IPC, temporary filesystem and device view. The only socket family it can create is AF_UNIX. Mask the host's home and service state, including host Unix sockets. Mount only the sealed runtime read-only. Drop all capabilities, forbid new privileges and bind the process tree to a nondelegated cgroup v2 with `KillMode=control-group`, 512 MiB and 128 tasks. Its inherited communication channel goes only to the trusted controller. Production workers must receive no credentials, writable control sockets or unrelated open file descriptors.

The host independently checks the unit invocation, principal, cgroup identity, limits, namespace and filter settings and the actual driver, Chromium and renderer membership before dispatch. Bind the observation to boot identity, process start times and this invocation. Reject stale evidence or replacement of any pinned document, process or unit. Enforce containment from process creation through verified exit. Test with reachable host receivers for IPv4 and IPv6, TCP and UDP, with positive deliveries before the protected run. Retain the resulting receiver and kernel evidence through shutdown.

Use a fresh transient unit with automatic restart disabled. Supply the driver with controller-owned input and output pipes and discard its standard error. Close unrelated inherited descriptors before launching it. Require a private network namespace, `RestrictAddressFamilies=AF_UNIX`, a native syscall architecture and a syscall filter denying io_uring operations. Mask `/run`, `/var` and `/srv`, then bind the sealed runtime read-only. Check pathname and abstract Unix receivers as well as TCP and UDP. Bracket the whole observation window with successful controls. [Rehearsal unit settings](../scripts/linux_canary_driver.py)

Chromium must use its native user-namespace and seccomp sandbox. Reject flags that disable it. The driver has its own unit PID and network namespaces. Require the browser and renderers in the service cgroup, the renderer in a nested PID namespace and seccomp mode 2. Bind the browser and renderer lifetimes after the document loads. Inspect again immediately before and after the fill. For live dispatch, continuously track the cgroup, pinned processes and document identity through exit. A renderer restart, an unexpected executable, a new unaccounted descendant or a gap in evidence invalidates the observation. Keep the grant closed. Record the final cgroup removal and disappearance of the pinned process lifetimes.

## Observation, approval and dispatch

The supervisor owns a read-only observation channel to the live document. Bind the top-level frame, document loader and target DOM node at the first read. Read the exact input value before dispatch and after the one fill. The effect adapter may invoke only the fixed fill on the pinned element. It receives no observer handle, executable script, selector, bearer credential or general-purpose command. A worker acknowledgement alone never establishes the post-state. Discard by closing the browser tree. A fresh, separately admitted read of the enrolled page must find the field empty.

The source reader has its own restricted identity and egress permission for one enrolled HTTPS host and port. Deny redirects, validate TLS and the enrolled response digest, then fulfill the browser's one intercepted navigation at the original URL. For a live canary, the field changes only in this local rendering of the enrolled site's bytes. Nothing is sent to the website. The exact post-fill snapshot verifies the effect. The later empty-field check uses separate read authority to confirm that the transient state disappeared. It cannot establish whether an earlier fill occurred and consumes no action grant.

For live use, the host must authenticate the observer and effect peers separately. A trusted controller owns the browser connection and grants only fixed methods on distinct sessions. The observer may read the frame tree and DOM snapshot. The effect capability may fill its pinned element once. Expose neither a raw CDP session nor an evaluation, navigation or selector API to either caller. Test cross-role denials. Readback trusts Chromium's state and is independent of the fill acknowledgement. The rehearsal's controller exposes fixed Python operations and reads a separate CDP session on the same browser. Separate production principals still require qualification.

On the trusted host, order target withdrawal and the final authorization to dispatch against the same authoritative record. Revalidate the enrolled version, signed decision capsule, exact permit, worker, fence and fresh pre-state at reservation and dispatch. Atomically consume the one deployment-wide grant even on cancellation. A duplicate or restart may retrieve only the original status. Loss of independent observation, containment, shutdown or definite outcome after dispatch closes admission and preserves the unknown receipt and quarantine. A read-only dashboard service, its credentials and its socket grant no authority for a fill. [Approval and recovery rules](production-effect-policy.md)

Linux owns the single first-action grant across all hosts. No other host may execute it. Commit and sync the unique grant reservation to stable storage, then commit and sync its dispatch marker before sending the fill. A crash before the marker leaves a spent, cancelled reservation. A crash after the marker without a proven result leaves a spent, quarantined unknown outcome. Test both crash points. Fence restoration of older storage against an independently protected grant high-water mark. An unavailable or inconsistent mark closes admission.

## Qualification and release

The host rehearsal uses a separate transient unit, a fixed scriptless fixture and a synthetic Fade decision. It must exercise the actual permit and WEIR dispatch path, exact independent readback, discard in a second browser, a lost response, conflicting and post-restart replay, verified process exit and zero observed deliveries. It has no live destination or persistent action listener.

Rehearsal authorities use ephemeral caller credentials and private fixture stores. Live verification must require its protected production issuer, key, audience and grant store. Reject unsigned fixture decisions, any test signing key or audience, and a rehearsal permit. Isolate fixture authorities from production signing keys and grant storage before provisioning either. The present rehearsal runs the trusted host inspector and the test authority together on an unenrolled host. The ordinary service must reject the rehearsal permit even with an authenticated caller.

Production admission also requires protected owner enrollment, two distinct human passkey decisions, independent verification of the signed capsule, the deployment-wide grant and a reviewed live adapter. Run the rehearsal suite against the actual live adapter and compare its resolved isolation settings with the qualified settings before admission. Demonstrate denial for wrong or withdrawn authority, changed page or worker, failed isolation and missing evidence, including the unknown-outcome path. Only the designated owner can authorize the named first live action.
